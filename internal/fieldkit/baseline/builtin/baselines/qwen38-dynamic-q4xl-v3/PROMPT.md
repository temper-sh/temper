# Qwen3.8 Dynamic baseline operator contract

This package materializes and checks one exact local profile. It does not
claim that this model is best, change an existing service, publish evidence,
or qualify a different machine. The source evidence is one Apple M5 with
32 GiB unified memory; this run is the portable second-machine witness.

Before consent, show the exact `temper field-kit baseline explain
qwen38-dynamic-q4xl@3` output. Consent must name
`qwen38-dynamic-q4xl@3` and choose `keep` or `restore`. The dedicated Temper
root must not already exist. A recommendation or a prior model download is not
consent.

Use `temper field-kit baseline run` for the normal workflow. It advances the
declared immutable stages in order and records each exact output identity
before beginning the next stage. `run-next` is the one-stage recovery and
inspection form. If interrupted, rerun either command with the same session;
Temper retries the first pending stage, and its install, fetch, apply, check,
and remove stages reconcile the same desired state. Never bypass a failed
safety or integrity check.

The live protocol uses loopback only. It checks model discovery, exact
non-streaming and streaming control, single and parallel tool calls, tool
continuation, four-turn history, cancellation/recovery, and a three-request
soak. It stores hashes and structured measurements, not generated content.
Stop on thermal warnings, abnormal swap growth, integrity failure, repeated
process exit, or any effect outside the disclosed dedicated root.

For `keep`, the exact model, template, runtime, router, config generation, and
receipts remain below the dedicated root. For `restore`, Temper first removes
its software installation, verifies the root ownership marker, then removes
the entire dedicated root. The session and final report must be outside that
root and remain local unless the user explicitly exports them.
