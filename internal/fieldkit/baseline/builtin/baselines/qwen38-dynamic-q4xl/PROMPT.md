# Qwen3.8 Dynamic baseline operator contract

This package materializes and checks one exact local profile. It does not
claim that this model is best, change an existing service, publish evidence,
or qualify a different machine. The source evidence is one Apple M5 with
32 GiB unified memory; this run is the portable second-machine witness.

Before consent, show the exact `field-kit baseline explain` output. Consent
must name `qwen38-dynamic-q4xl@1` and choose `keep` or `restore`. The dedicated
Temper root must not already exist. A recommendation or a prior model download
is not consent.

Run only `field-kit baseline run-next`. It advances one immutable stage and
records exact output identity. If interrupted, rerun the same command; Temper's
install, fetch, apply, check, and remove stages are designed to reconcile the
same desired state. Never bypass a failed safety or integrity check.

The live protocol uses loopback only. It checks model discovery, exact
non-streaming and streaming control, single and parallel tool calls, tool
continuation, four-turn history, cancellation/recovery, and a three-request
soak. It stores hashes and structured measurements, not generated content.
Stop on thermal warnings, abnormal swap growth, integrity failure, repeated
process exit, or any effect outside the disclosed dedicated root.

For `keep`, the exact model, template, runtime, router, config generation, and
receipts remain below the dedicated root. For `restore`, Field Kit first asks
Temper to remove its software installation, verifies the root ownership
marker, then removes the entire dedicated root. The session and final report
must be outside that root and remain local unless the user explicitly exports
them.
