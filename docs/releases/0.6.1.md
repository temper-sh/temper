# Temper 0.6.1

Temper supports Splash 1.7.0's local model preparation and native-engine
recovery. Opening an artifact directory in Finder no longer makes it fail
verification merely because Finder added a `.DS_Store` file.

## Upgrade from 0.6.0

Finish active work and stop running Temper layouts before upgrading:

```sh
temper stop
brew update
brew upgrade temper-sh/temper/temper
temper version
```

Upgrading the CLI preserves saved selections. Engine and model choices remain
catalog selections; this CLI release does not update them automatically.

## What changed

- **Splash 1.7.0 compatibility.** Preparation uses the release's local API and
  passes the selected chat template explicitly. Weights remain in the shared
  Hugging Face cache; setup no longer budgets the obsolete native weight copy.
  Interrupted preparation can resume, and completed preparation is verified
  on reuse. Saved Splash 1.3.2 executions retain their existing behavior.
- **Owned native recovery.** Managed Splash layouts recognize a replacement
  native engine only when its command and frontend ownership match the
  selected execution. Fixed-process experiments report a restart as a failure
  while retaining authority to clean up the verified replacement. A captured
  child can also be stopped after its frontend exits, with its exact process
  lifetime still verified.
- **Finder metadata tolerance.** Artifact verification accepts unlisted regular
  `.DS_Store` files inside valid artifact directories without changing receipts
  or metadata. Selected files, symlinks, unexpected directories and other extra
  files retain their existing checks.

## Verification and compatibility

Full offline Go tests, vet and race checks pass. Native Splash 1.7.0 checks
with cached weights cover chat and tool streaming, tool-result follow-up,
client cancellation, managed recovery and shutdown. Restarted fixed-process
experiments fail and clean up correctly. These verify runtime compatibility;
they do not establish a general model-quality or performance improvement.

The Finder regression reproduces the original rejection and covers unchanged
inspection results and receipts, repeated checks, selected-file corruption,
and refusal of metadata symlinks, directories and other hidden files.

Splash 1.4–1.6 is refused because those releases lack the required template
override. Executions using the new Splash preparation and recovery contract
require Temper 0.6.1 or later. Existing roots, catalogs and saved Splash 1.3.2
executions remain supported.
