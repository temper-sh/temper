# Temper 0.5.1

This patch keeps measured memory use visible when macOS gives the GPU more
memory than it had when the measurement was taken. Temper now shows the tested
peak again instead of a smaller, incomplete estimate. The patch also removes an
unused memory prediction from setup output.

## Upgrade from 0.5.0

Finish active work and stop running Temper layouts before upgrading:

```sh
temper stop
brew update
brew upgrade temper-sh/temper/temper
temper version
```

Upgrading the CLI leaves saved model selections unchanged.

## What changed

- **Measurements apply at a larger GPU memory budget.** macOS limits how much
  memory the GPU may use. Temper reads that limit from Metal, Apple's GPU
  interface. A catalog memory measurement used to apply only when your limit
  matched the tested limit exactly. Now it also applies when your limit is
  larger and the engine cannot use more memory than it had during the test.
  That covers llama.cpp with `fit: off`, and Splash or Kapitsa when their own
  memory ceiling is within the tested limit. Chip and RAM must still match.
  Other engines still need the same limit, and a smaller limit still falls back
  to an estimate.

  For example, the Qwen Medium measurement was taken with a 24 GiB manual
  limit (`iogpu.wired_limit_mb`). On an Apple M5 with 32 GiB, the macOS default
  is 25,559 MiB. Setup now shows the measured 21.11 GiB peak there. Before, it
  showed an incomplete 18.87 GiB estimate that left out the context cache.
  When a measurement does not apply because of the GPU limit, the reason now
  says so, separately from a different chip or RAM size.
- **Unused prediction removed.** An older prediction assumed that one model
  stays loaded on the GPU all the time. Setup loads each preset on demand, so
  that prediction never applied and always reported `not-applicable`. JSON
  output no longer contains `memory_prediction`, or the always-zero
  `engine_envelope_bytes` field under `memory_estimate`. Memory admission,
  refusals and wired-memory advice are unchanged.

The [memory accounting contract](https://github.com/temper-sh/temper/blob/v0.5.1/docs/contracts/memory-estimates.md)
describes when a measurement applies.

## Compatibility and distribution

Existing catalog files, Temper roots, saved selections and manifests remain
supported. Manifests still accept `defaults.gpu_memory_utilization`; Temper no
longer reads it. Scripts that read `memory_prediction` or
`engine_envelope_bytes` from command output need to drop those fields. Scripts
consuming command output should pin an exact Temper version.

The direct macOS ARM64 ZIP is signed and notarized. Homebrew provides a source
formula and a separate ARM64 bottle.
