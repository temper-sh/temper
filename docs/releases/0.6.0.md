# Temper 0.6.0

Saved layout changes now take effect when you close the editor. Temper waits
for active requests before restarting, keeps harness model lists synchronized,
and stops cleanly when idle clients remain connected. Setup Review also avoids
rechecking every installed software file while a model is running.

These notes cover Temper changes from 0.5.0 through 0.6.0, including the
memory-accounting fixes first released in 0.5.1.

## Upgrade from 0.5.0

Finish active work and stop running Temper layouts before upgrading:

```sh
temper stop
brew update
brew upgrade temper-sh/temper/temper
temper version
```

Upgrading the CLI preserves saved model selections.

## What changed

- **Layout edits apply on close.** Save changes to the running layout's models
  or serving settings, then close `temper layout`. Temper restarts that layout
  and refreshes its selected harness configurations. Renaming alone does not
  restart it; a stopped layout stays stopped.
- **Restarts wait for active requests.** Interactive activation and editor
  apply show a waiting notice. Ctrl-C cancels that wait without changing the
  running generation or harness files. Saved edits remain available to apply
  later. Scripted `--json` transitions and stop still refuse active requests.
- **Idle clients no longer block stop.** An idle HTTP connection or an open
  router event stream can remain connected when you stop a layout. Requests
  already in progress still prevent stopping.
- **New models join Default.** In guided configuration, newly selected presets
  join an existing Default layout on demand. If other layouts exist, Review
  offers a switch for that addition. Existing loading/default choices and other
  layouts are preserved. Without Default, use the layout editor to place them.
- **Review is quicker and clearer.** It uses exact installation receipts
  instead of hashing installed software, and shows download/disk totals and a
  readable file table. Preparation and activation retain full verification.
  Preset cards show a compact memory figure and download size; Review omits
  internal measurement records and manual GPU-memory tuning advice.
- **Catalog description edits preserve unrelated data.** Editing one
  description no longer inserts optional defaults into other presets. JSON
  and YAML retain untouched values and field absence.
- **Measured memory applies at a larger GPU budget.** A catalog measurement
  remains applicable when macOS supplies a larger Metal memory allowance and
  the engine cannot grow beyond the tested budget: llama.cpp with `fit: off`,
  or Splash/Kapitsa with a sufficient fixed memory ceiling. Chip and RAM must
  still match. A smaller budget or an engine without that bound still falls
  back to an estimate. A mismatch now identifies the GPU budget separately
  from chip or RAM differences.
- **Unused memory prediction removed.** The old prediction assumed a model
  remained loaded permanently, so it did not apply to on-demand layouts.
  Temper no longer emits `memory_prediction` or the always-zero
  `memory_estimate.engine_envelope_bytes` field.

Maintenance also removes an adjacent-port assumption from parallel tests.

## Decision-model preparation

Reviewed serving contracts, packaging requirements and adapter gaps for
Glide 9B and Base Labs Elephant/Joey as the first integration candidates.
The preparation identifies shared System One transport, differences in score
semantics, and unresolved Apple Silicon runtime support. It informs the next
implementation decision; 0.6.0 does not yet provide decision-model adapters
or supported decision-model presets.

## Verification and compatibility

Full offline Go tests, vet and race checks pass. Native checks with cached
E2B/Qwen3.5 4B weights verify waiting restart, cancellation, editor apply and Pi
synchronization, Review during generation, and shutdown with idle HTTP/SSE
clients. These are lifecycle checks, not model-quality evaluations.

Existing roots, catalogs and execution locks remain supported. Manifests still
accept `defaults.gpu_memory_utilization`, but Temper no longer reads it. Scripts
that consume the removed memory fields need to stop expecting them. Review may
report software as present after on-disk damage; preparation and activation
detect that damage. A request arriving at the instant shutdown begins can
receive a closed connection. Scripts consuming command output should pin an
exact Temper version.
