# Temper 0.4.0

Temper 0.4.0 adds separate preset and layout editors, simpler guided setup,
Pi/PiG/Hermes integration, and remembered start/stop commands. The catalog adds
Qwen with Kapitsa and measured memory guidance for selected presets.

## Upgrade from 0.3.x

Finish open Field Kit studies and stop active Temper layouts before upgrading:

```sh
temper layout stop
brew update
brew upgrade temper-sh/temper/temper
temper version
temper update
```

`temper update` reviews and installs catalog changes for your saved choices.
To resume a stopped layout from an older Temper version, select it explicitly
once with `temper layout activate ID`. After that, `temper stop` and
`temper start` remember both the layout and its listening address.

## What changed

- **Simpler setup.** The wizard follows Presets → Harnesses → Review. First
  setup creates a Default layout with the selected models available on demand.
  Running setup again preserves existing layouts. Context remains a separate
  prompt with Apply and Cancel.
- **Preset and layout editors.** `temper preset` opens the editor for forks
  and independent copies, including settings, weights and chat templates.
  Saved presets appear directly in `temper layout`, where you choose membership,
  startup models, the default model and idle settings. Both editors support
  keyboard and mouse input. Saving a draft does not change a running layout;
  activation remains explicit. Updates preserve fork overrides, show changes
  beneath them and retain independent copies.
- **Pi, PiG and Hermes integration.** Select integrations on the wizard's
  Harnesses screen. Layout activation synchronizes the included chat models
  and endpoint into the reviewed configuration files, preserving unrelated
  settings. Hermes keeps automatic model discovery enabled.
- **Remembered start and stop.** `temper start` resumes the selected layout;
  `temper stop` unloads its models. Selection survives stops and reboots.
  Shutdown and interrupted-start recovery verify process ownership and refuse
  uncertain state or connected clients. Outgoing router-to-engine keepalives
  no longer prevent stopping an otherwise idle layout.
- **Qwen with Kapitsa.** The catalog offers Qwen3.8-27B MLX 4-bit with a
  DFlash2 draft on the pinned Kapitsa 0.2.9 runtime. Temper installs the native
  engine, verifies both model inputs and preserves its local calibration
  across restarts. The preset uses a 98,304-token context, thinking off and
  disk caching disabled. See the
  [configuration and measurements](https://temper-sh.github.io/models/qwen3.8-27b/layouts/kapitsa-mlx4.html).
- **Muse and Gemma catalog choices.** Muse adds a DFlash2 preset at 131,072
  tokens while retaining the plain 57,344-token option. Gemma 26B uses plain
  decoding at 131,072 tokens; Gemma 31B uses MTP width 3 at 40,960. Both Gemma
  presets default to a 1,024-token reasoning budget.
- **Memory guidance and installation planning.** Applicable measured loaded
  and peak memory take precedence over estimates. Estimates account for
  supported KV/context caches and distinguish unknown allocations. Changing
  execution inputs invalidates incompatible measurements. Python-engine
  installation previews include the pinned interpreter and package downloads,
  disk allowances and reuse of verified installations.
- **More preset controls.** Native reasoning-token budgets support the selected
  Gemma presets while preserving client overrides. llama.cpp presets can place
  a chosen number of MoE expert layers on the CPU independently of GPU-layer
  settings; unsupported GPU-memory splits remain explicitly unknown.

The [preset](https://github.com/temper-sh/temper/blob/v0.4.0/docs/contracts/user-presets.md),
[layout](https://github.com/temper-sh/temper/blob/v0.4.0/docs/contracts/layouts.md)

## Compatibility and distribution

Existing catalog files, Temper roots and user presets remain supported.
Upgrading the CLI leaves saved selections unchanged; new catalog features
declare their minimum Temper version. Scripts consuming command output should
pin an exact Temper version.

The direct macOS ARM64 ZIP is signed and notarized. Homebrew provides a source
formula and a separate ARM64 bottle. Installing the CLI does not download models
or start a layout.

Memory observations apply to their recorded machine, configuration and workload;
they do not establish fit on every Mac. Fit on 8/16 GiB machines remains
unverified. Kapitsa requires Apple M1 or newer and macOS 14 or later; its M5
measurements do not establish performance or memory use on other chips.
