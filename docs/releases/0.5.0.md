# Temper 0.5.0

Temper 0.5.0 adds explicit replacement and removal of retired presets,
operator-controlled thinking settings, optional preset defaults, and a simpler
compute selector in guided setup.

## Upgrade from 0.4.0

Finish active work and stop running Temper layouts before upgrading:

```sh
temper stop
brew update
brew upgrade temper-sh/temper/temper
temper version
```

Upgrading the CLI leaves saved model selections unchanged. Use `temper update`
to review updates for those selections, or `temper configure` to change them.
Catalog contents and model settings are documented in the
[preset directory](https://temper-sh.github.io/catalog/), separately from this
software changelog.

## What changed

- **Explicit preset retirement.** Saved choices with a withdrawal notice appear
  under Retired in setup. Keep using is the default. Replace and Remove require
  review; replacement preserves layout references and uses successor defaults,
  or an already-selected successor's settings. Authored overrides are not
  silently transferred. Existing clients using the old API model ID must select
  the successor explicitly.
- **Recoverable replacement and cleanup.** Temper prepares the successor before
  switching, retains interrupted work for `configure --resume --prepare`, and
  cleans only newly unused managed material. Shared HF weight deletion needs
  separate consent. Temper checks client support before switching, passes exact
  filenames and verifies removal across cached revisions. Failed cleanup can be
  resumed without repeating successful activation. `--discard-retirement`
  abandons pending work while retaining the current selection and remaining
  files, including when the intent is unreadable.
- **Consistent retirement review.** Staged successors remain selected through
  Review. Retirement identity comes from applied provenance, so an unapplied
  edit cannot retire an installed independent copy. Catalog notices accumulate
  until a maintainer removes them; a withdrawal can be reversed without
  repurposing a preset ID.
- **Optional defaults and thinking controls.** Preset authoring supports omitted
  sampling controls and independent reasoning capability/default declarations.
  Editors expose supported thinking mode and effort choices. Supported explicit
  request settings override preset fallbacks; omitted controls remain omitted
  through compilation and rendering. Harness integration reflects the declared
  reasoning capability.
- **Compute selection with Apply and Cancel.** Guided setup stages CPU/GPU
  changes in a separate prompt, matching Context. Cancellation preserves the
  saved choice and memory assessment.
- **Clearer memory guidance.** Preset cards omit the generic fit suffix.
  Wired-memory advice distinguishes optional headroom from a real budget
  refusal, retaining detailed limits and the manual adjustment command.
- **Rapid MLX adapter corrections.** Compatible Rapid runtimes receive the
  configured context length explicitly. Disabling disk caching uses the native
  disable flag, including when cache capacity is set to zero. Older runtime
  versions retain their supported command syntax.
- **Maintenance.** Go dependencies are refreshed and the README includes a
  compact setup-wizard demonstration.

## Compatibility and distribution

Existing Temper roots, saved locks and user presets remain supported. Retirement
does not automatically replace or delete a saved model. Applying a retirement
uses the existing Install and start behavior, including for a stopped root.
Upgrade the CLI before refreshing the catalog: records using the new controls
require 0.5.0 and are unavailable to older clients. Existing saved locks remain
usable on their compatible CLI version.
Scripts consuming command output should pin an exact Temper version.

The macOS ARM64 ZIP is signed and notarized. Homebrew provides a source formula
and a separate ARM64 bottle. Installing the CLI does not download model weights
or start a layout.

The [setup](https://github.com/temper-sh/temper/blob/v0.5.0/docs/contracts/init.md),
[preset](https://github.com/temper-sh/temper/blob/v0.5.0/docs/contracts/user-presets.md)
and [execution-lock](https://github.com/temper-sh/temper/blob/v0.5.0/docs/contracts/execution-lock.md)
contracts describe the detailed behavior.
