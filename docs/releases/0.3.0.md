# Temper 0.3.0

Temper installs and manages a local AI stack on Apple Silicon Macs. Choose
model presets in a guided setup; Temper downloads the files, starts the models
and serves them to chat and coding apps through one local OpenAI-compatible
API. In this release you can make your own presets as files, each Temper
folder gets its own engine ports, and the catalog moves to newer engines.

## Upgrade from 0.2.0

```sh
brew upgrade temper-sh/temper/temper
temper update
```

`temper update` shows what changes for each saved preset, installs it and
restarts the running layout. Qwen with Splash now runs Splash 1.3.2, which
needs Temper 0.3.0; on 0.2.0 that preset stays as it is and `temper update`
says it needs a newer Temper.

Your `~/.temper` folder keeps its engine ports, so the upgrade itself restarts
nothing. A Temper folder elsewhere moves to its own ports the next time its
layout starts.

## What changed since 0.2.0

- **Your own presets.** A preset of your own is a file in
  `~/.temper/presets.d`: a *fork* of a catalog preset that changes some
  settings and follows catalog updates, or a *copy* that holds every value.
  `temper preset fork`, `copy`, `check` and `fields` make and check them;
  `temper preset weights` and `template` add other weights of the same model
  or another chat template, with sizes and hashes from Hugging Face, or your
  own template file. `temper catalog compile --root ~/.temper --preset ID`
  builds an exact lock for the execution commands. The guided setup does not
  list your presets yet, and the catalog makes no claim about them. See
  [Your own presets](https://github.com/temper-sh/temper/blob/v0.3.0/docs/contracts/user-presets.md).
- **Separate engine ports for each Temper folder.** Before, every folder
  started its engines on the same ports, so a second folder, such as a Field
  Kit run, could reach another folder's engine. `~/.temper` keeps port 10001;
  other folders get their own block. Serving refuses to start, and names the
  process, when another program holds one of those ports.
- **Newer engines** in the catalog published with this release: llama.cpp
  b11716, llama-swap v265, CrispEmbed v0.17.12 and Splash 1.3.2. Qwen with
  Splash uses a 112,000-token window under its 24 GiB memory cap, because
  Splash 1.3.2 refused 118,000 on the tested 32 GiB Mac. TranslateGemma uses
  the template inside its weights with llama.cpp's own language-code handling.
- **Two experimental engines** for your own presets: Rapid MLX 0.16.3 and vLLM
  Metal 0.31.0. The catalog has no presets for them yet.

## Compatibility

Temper keeps these working across its releases: the published catalog files,
your Temper folder (`configuration.json`, the stored catalog and
`temper-root.json`), and, from this release, your preset files in `presets.d`
(`temper-preset/v1`). Command output, including `--json`, may change in any
release; scripts that use it should pin an exact Temper version.

## Distribution and limits

The direct macOS ARM64 ZIP on this page is signed and notarized. Homebrew
provides a source formula and a separate ARM64 bottle.

Memory estimates and recommendations do not establish fit or answer quality on
every Mac. Fit on 8/16 GB Macs is not verified. Model downloads can be many
gigabytes. Serving is local to your Mac; Temper has no telemetry or background
updater.

Report problems at
[github.com/temper-sh/temper/issues](https://github.com/temper-sh/temper/issues).
